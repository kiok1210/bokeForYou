# EchoPod · 播客与视频缓存播放器

把 YouTube 上的内容搬到本地：**搜到 → 缓存 → 分类 → 离线听/看**，附可跟读的逐字稿与中文对照。

四种内容模式任选：**中文播客 · 英文播客 · 长视频 · 短视频**。

和 VinylBox（`musicForYou`）是同一套技术底座下的两个产品：一个听歌，一个听 / 看节目。

## 功能

- **四种内容模式**：中文播客 / 英文播客 / 长视频 / 短视频。一次切换同时换掉四件事——语言、时长区间、媒介形态（纯音频还是连画面一起下）、整份分类目录，不需要分别去调
- **看视频也看字幕**：长视频与短视频会把画面一起缓存，播放器里直接播；逐字稿照旧可点行跳转
- **界面风格可选**：4 套主题（黑金 / 午夜蓝 / 森绿 / 日落），配色与圆角一起换，设置里点一下即时生效
- **字幕可控**：播放器上一键开关字幕（关掉只剩声音，适合纯听力练习，且不会再去拉取逐字稿）；字号四档可调，设置里选或逐字稿面板底部就地调
- **开箱即用**：yt-dlp 与 ffmpeg 随安装包内置，装完直接搜索 / 缓存，不需要 Python、不需要联网装组件
- **边听边缓存**：点「边听边缓存」即刻开听（解析直链边收边播），同时后台把这一集存到本地；听完前缓存通常已就绪，下次自动走本地文件（断点续听也照样生效）
- **我的源**：左侧可自定义搜索源——粘一个频道 / 播放列表链接，或写一句关键词（如 `english listening practice`），钉在侧栏点一下就能拉到最新单集
- **热门榜（自动抓取）**：按当前模式的 5 个安全主题分类关键词自动抓一批高播放量内容，按播放量排序、同一节目限流、每种模式各缓存一份 6 小时，可一键「换一批」
- **内容合规过滤**：检索、热门榜、分类发现的结果都会先过一遍类别词表，剔除政治、战争、恐怖、色情、赌博、毒品、仇恨等主题（详见下文）
- **搜索 / 链接解析**：支持关键词搜索；也支持粘贴**频道主页或播放列表**链接，一次拉出最近几十集
- **精选节目**：分类里内置知名节目（Lex Fridman Podcast、BBC Learning English、吴晓波频道、MIT OpenCourseWare、BBC Earth…），**点节目名即拉取它的最新内容**，打开应用就有东西可挑
- **分类发现**：每个模式各有一套分类（中文播客 8 个、英文播客 8 个、长视频 6 个、短视频 6 个），每个分类都有醒目的「搜索热门」按钮，不知道听什么就点它
- **自动归类**：下载后按标题 + 节目名判断主题，直接落到对应分类；随时可在列表里手动改
- **分类看板**：每个分类一张卡，显示已缓存集数与总时长，支持「播放全部」
- **本地缓存**：下载原始音轨（M4A）并保存封面，缓存后完全离线可听
- **断点续听**：记住每集听到第几秒，下次自动接着播；可配「跳过片头」
- **倍速播放**：0.75× ~ 2.5×，全局默认倍速可设置
- **睡眠定时**：15/30/45/60/90 分钟后自动暂停
- **逐字稿**：抓取 YouTube 自带字幕（含自动生成），非英语自动附带中文翻译，**点击任意一行可跳转到该时间**
- **列表管理**：收藏、按分类筛选、搜索缓存、在文件夹中显示、单集删除、清空缓存
- **下载队列**：并发下载、实时进度 / 速度 / 剩余时间、任务取消
- **代理兼容**：跟随系统（含 PAC 脚本）/ 手动指定（HTTP、SOCKS5）/ 强制直连

## 环境要求

- Windows 10 / 11 x64
- Node.js 18+（**仅开发与打包需要**，装完的安装包运行时不需要）

### 下载核心已随包内置

`resources/bin/yt-dlp.exe` 与 `resources/bin/ffmpeg.exe` 会被打成安装包的一部分
（`<安装目录>\resources\bin\`），**装完即用：不需要 Python，也不需要联网初始化**。

组件按以下优先级挑选，方便替换成自己的版本：

1. 环境变量 `YTDLP_PATH` / `FFMPEG_PATH`
2. 应用私有目录 `%APPDATA%\EchoPod\bin`
3. **随包内置的 `resources\bin`（默认走这里）**
4. Python 模块 `yt_dlp` / `imageio-ffmpeg`（若本机已装过）
5. 系统 PATH

只有当以上全部缺失时，界面才会出现「初始化组件」的兜底入口（走 pip 安装到 `pylibs`）。

要更新内置组件，替换 `resources/bin` 下的两个 exe 后重新 `npm run dist` 即可。

## 缓存位置

全部数据位于 `%APPDATA%\EchoPod`：

```
EchoPod/
├── media/         音频文件（<视频ID>.m4a）
├── covers/        封面图（<视频ID>.webp）
├── transcripts/   逐字稿缓存（<视频ID>.json）
├── subs/          下载字幕的临时目录
├── pylibs/        兜底初始化时的 Python 依赖（内置组件可用时不会用到）
├── library.json   单集索引（含模式、分类与播放进度）
├── trending-<mode>.json  热门榜缓存，每种内容模式一份（6 小时有效）
├── sources.json   我的源（自定义频道 / 关键词）
├── progress.json  边听边缓存时的进度暂存（缓存完成后并入索引）
└── settings.json  设置
```

启动时会自动归集 `media/` 中尚未入索引的音频文件，并异步补齐单集信息。

## 可移植创新点（双向）

`src/shared/portable/` 下是与业务无关的纯逻辑，**不 import electron、不 import react、不读写文件**，
可以整目录复制进 VinylBox 直接使用：

- **`playback.ts`** — 倍速档位与吸附（`nearestRate` / `cycleRate`）、断点续听（`resumePosition` / `isFinished` / `progressRatio`）、睡眠定时（`sleepDeadline` / `sleepRemainingSeconds` / `shouldSleep` / `formatClock`）
- **`collections.ts`** — 通用分组（`groupBy`，保序 + 可指定排序）、文本归一化（`normalizeText`）、关键词打分（`scoreByMarkers` / `inferBucket`）、关键词排序（`rankByKeyword`）

搬到 VinylBox 后能立刻补上的能力：

1. **断点续听的音乐版**：长混音 / DJ Set / 专辑连续播放场景同样需要「接着上次听」；`resumePosition` 已处理「进度太浅不记、接近结尾不记」的边界
2. **倍速播放**：有声书与长音频必备，`PLAYBACK_RATES` + `nearestRate` 直接可用
3. **睡眠定时**：睡前听歌场景的刚需，UI 只需接 `startSleep` / `cancelSleep` 与 `sleepRemaining`
4. **集合 / 歌单分组**：`groupBy` 可把「按艺术家 / 按年代 / 按风格」的分组逻辑统一掉，替代散落各处的 `reduce`
5. **自动打标**：`inferBucket` 就是本项目「下载即归类」的实现，换成音乐场景的标签词表即可复用

对应的调用样例见 `src/shared/portable/` 内各函数的注释。

### 来自 VinylBox 的模块（musicForYou 原创，已同步到本仓库）

- **`subtitles.ts`** — LRC / WebVTT / 纯文本解析、文本清洗、语言检测（假名与谚文优先于汉字，中日混排不会误判）、按时间就近做双语对齐
- **`ytdlp-output.ts`** — 下载进度行解析、阶段标记（转码 / 合并 / 写元数据）、英文报错中文化、链接与合集判别、临时故障识别
- **`format.ts`** — 时长 / 体积 / 相对时间格式化、平台标题清洗（emoji 与 `Official MV` 之类）、检索词候选生成
- **`concurrency.ts`** — 并发池 `TaskQueue`、`mapLimited`、去抖与节流
- **`text-rules.ts`** — 关键词规则匹配内核，即 `inferBucket` 的通用底座

本仓库可以立刻用上的地方：

1. **`parseVtt` / `detectLanguage`** — `transcripts.ts` 里现有一份复制过去的实现，改为引用 `subtitles.ts` 后两边共用同一份，改一处两边受益
2. **`friendlyYtDlpError`** — `ytdlp.ts` 的报错中文化与此完全一致，可直接替换
3. **`searchCandidates`** — 由标题生成检索词，「换一批」时能生成更准的查询
4. **`TaskQueue`** — 替换 `downloader.ts` 里手写的并发队列
5. **`isTransientFailure`** — 判断限流 / 超时，用于决定失败结果要不要落缓存

### 同步方式

任一项目新增模块后，把 `src/shared/portable/*.ts` 复制到另一侧同名目录即可：
该目录内的模块之间只用相对路径互相引用，也不依赖任何外部类型，复制即生效。
VinylBox 侧同样已建立 `src/shared/portable/`，并把自身重复实现改为引用它。

## 内容模式

界面顶部的四个按钮就是模式。切换后分类导航、热门榜、搜索结果与「我的单集」会整体跟着换。

| 模式 | 语言 | 媒介 | 时长区间 | 画幅 | 分类数 |
| --- | --- | --- | --- | --- | --- |
| 中文播客 | 中文 | 纯音频 | 5 分钟以上 | 方图 | 8 |
| 英文播客 | 英语 | 纯音频 | 5 分钟以上 | 方图 | 8 |
| 长视频模式 | 中英混合 | 含画面 | 20 分钟以上 | 横屏 | 6 |
| 短视频模式 | 中英混合 | 含画面 | 3 分钟以内 | 竖屏 | 6 |

模式不只是"换一个搜索词"，它同时约束四件事：

- **时长**：检索时按单集时长筛选。严格筛选后条数不足会自动放宽补齐，不会给出空白列表；短视频模式下时长拿不到的条目会被跳过（无法确认是短片）
- **媒介**：音频模式只下音轨（M4A / MP3），体积小、适合后台听；视频模式下 MP4（默认 1080p 以内，由 ffmpeg 合并），播放器直接渲染画面
- **画幅**：短视频按竖屏渲染，长视频按横屏铺满；配合「放大播客主体」可以把画面铺到整屏
- **归类**：下载后按标题 / 节目名在**该模式自己的**分类目录里自动归类。不同模式允许有同名分类，不会串味

缓存是**分模式隔离**的：「我的单集」、分类看板、热门榜都只看当前模式的内容；底层缓存目录共用，不会重复占地方。

### 视频模式的两点差别

- **不做边看边缓存**：视频体积大、码率波动也大，点缓存直接入队，下完再播（音频模式的「边听边缓存」照旧保留）
- **没有 ffmpeg 时**退化成单文件 MP4，清晰度低一些，但不会直接失败

逐字稿能力完全保留，可以一边看画面一边点行跟读。

### 播放内核的一条硬约束

音频与视频共用界面上**唯一**的一个 `<video>` 元素：

- 音频播客只出声，元素仍然**留在渲染树里**（用绝对定位 + 透明度隐藏，**不要用 `display: none`**）
- 一旦把它移出渲染树，Chromium 不会为该元素建立媒体加载管线，边听边缓存这类网络流会停在「已暂停」，而且**没有任何报错**——排查时很容易误判成网络问题

同一处还有两层兜底，改动播放器时别删：

- 网络流刚写进 `src` 时首帧 `play()` 常被拒，真正起播靠 `canplay` 事件补播
- 加载失败会自动重新解析直链并重试（直链被上游提前作废是最常见原因），重试仍失败才提示用户

## 热门榜与内容合规

### 热门榜怎么来的

- 抓取词只取自**当前模式**里 5 个内容风险稳定的分类，直接复用各分类的关键词（中文模式用中文词、视频模式用视频词），**不去追时事、政治、战争这类话题的热度**
- 5 个查询并发执行，合并去重后按播放量降序；拿不到播放量的条目保持 YouTube 的相关性顺序
- 同一节目最多上榜 3 条，避免整榜被单一频道占满
- 结果写入 `trending-<模式>.json`，6 小时内再进「热门」直接读缓存，离线也能看到上次的榜单；点「换一批」才会重新联网抓取

### 合规过滤

过滤在**所有对外检索入口**统一执行：关键词搜索、粘贴链接解析、分类发现、热门榜。命中即整条剔除，并在界面提示「已按合规策略过滤 N 条内容」。

词表定义在 `src/shared/moderation.ts`，按类别组织：

| 类别 | 覆盖示例 |
| --- | --- |
| 政治与时政 | politics / election / parliament / 政治 / 选举 |
| 战争与暴力 | war / battlefield / military conflict / 战争 / 军事冲突 |
| 恐怖与极端主义 | terrorism / jihad / extremism / 恐怖主义 |
| 色情与成人内容 | porn / nsfw / erotica / 色情 / 成人内容 |
| 赌博与毒品 | gambling / casino / cocaine / 赌博 / 毒品 |
| 仇恨与歧视 | nazi / white supremacy / hate speech / 纳粹 |

几点如实说明：

- 词表刻意**只使用通用类别词**，不含任何具体人物、国家、地区或事件名称，便于在不同地区法规下安全复用
- 这是**第一道闸**：按「标题 + 节目名」做关键词匹配，能拦住绝大多数明显违规内容，但**无法覆盖标题不含关键词的隐蔽内容**，它不等于内容审核
- 设置里可以关闭过滤，但默认开启，且**建议保持开启**
- 请遵守 YouTube 服务条款与所在地法律法规，仅缓存自己有权收听的内容

要收紧或放宽，直接增删 `MODERATION_RULES` 里对应类别的正则；设置面板会自动展示当前生效的类别清单。

## 分类目录

分类定义在 `src/main/catalog.ts`，每个分类包含三部分：

- `shows`    —— 精选节目清单，点节目名即按频道拉取最新单集
- `keywords` —— 「搜索热门」时拿去搜 YouTube 的英文词
- `markers`  —— 下载后自动归类的特征词（整词命中权重更高）

要加一个新主题（比如「电影与影视」），在 `CATEGORIES` 里追加一项即可，导航、看板、筛选下拉都会自动出现。

## 性能与内存

几处容易踩坑、已经处理掉的地方：

| 位置 | 做法 |
| --- | --- |
| 音频回传（`media://`） | 用流式响应，不再把整个音频读进内存；实测一期 58MB 的访谈不再产生等量内存峰值 |
| 播放进度 (`usePlayer`) | 进度是每秒 4 次的高频数据，改为**订阅式**（`subscribeTime`），只有播放器与逐字稿订阅，App 主体不再跟着重渲染 |
| 逐字稿（两三千行） | 行列表 `memo` 化，高亮改由 `focus()` **直接改 DOM 属性**，播放时不再重排整个列表；当前行用二分查找定位 |
| 界面刷新 | 进度条按 250ms 节流，肉眼无差别但重绘次数减半 |
| 进度写盘 | 10 秒回写一次（原 5 秒），减少磁盘 IO 与状态更新 |
| 列表封面 | 已缓存的用本地封面；未缓存的把 1280×720 缩略图降级为 320×180 小图 |
| 元数据补齐 | 启动时按 2 并发补齐（原串行），整批失败立刻停止 |
| 热门抓取 | 抓取并发压到 3，避免同时起一堆 yt-dlp 进程把内存顶起来 |
| 下载 | 开启 `--concurrent-fragments 4`，长节目提速且不显著抬高内存 |

## 技术栈

Electron 33 + React 18 + TypeScript + Vite（electron-vite），无 UI 框架依赖，样式为手写 CSS。

本地音频通过自定义 `media://` 协议供给渲染进程，支持 Range 请求以便拖动进度。

## 已知限制

- 需遵守 YouTube 服务条款，请仅下载你有权保存的内容
- 逐字稿依赖 YouTube 是否有字幕；纯音乐或关闭字幕的单集拿不到文本
- 内置组件已覆盖日常使用；只有当内置 exe 被删除或系统环境特殊时，才需要走兜底初始化（此时需能访问 PyPI）
